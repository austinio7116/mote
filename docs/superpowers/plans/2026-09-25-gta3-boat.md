# Boat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a rare, findable boat to Grand Thumb Auto III that moves only on water, moored at a shoreline the way the helicopter sits on a pad.

**Architecture:** The boat is a vehicle type in the existing `cars[]` array (`VEH_BOAT`, slot `NCAR-3`), exactly as the tank and helicopter are, so entering, exiting, the HUD, the minimap, damage and selling all work with no new plumbing. Its movement replaces `drive_car` with a `sail_boat` function, the mirror of `fly_heli`. "Only runs on water" is one predicate, `boat_afloat()`, consulted by the movement code, by the drown exemption in `physics_pass`, and by the exit gate — one answer, three callers, the same shape the helicopter's `heli_aloft()` already has.

**Tech Stack:** C99 freestanding, Mote engine ABI v47, `games/grandthumbauto3/`. Host emulator (`build_host/mote_host`) for verification; `gcc` for host builds, `arm-none-eabi-gcc` for device builds, both driven by `tools/mote build`.

**Spec:** None. This plan is written from the one-line request *"add a boat that can be found that only runs on water and is very rare like the helicopter"*. The design decisions and their rationale are recorded inline in each task, and in the comments the tasks tell you to write. Where the request is silent, the helicopter is the precedent and the plan says so.

## Global Constraints

These bind every task. Copy them into any subagent brief.

- **`GAME_RAM` is 134 KB at `0x2005E800` and currently has 1,020 bytes free.** One `Gta3VehMesh` is 576 bytes (`sizeof` measured, not estimated). The boat needs one, so Task 1 frees the space before Task 2 spends it. Check headroom after every task with the command in "Verification ritual" below.
- **`max_tris` is 850** and the worst measured whole-scene peak is about 790. Street furniture alone is 74. Anything this plan adds to the flat-triangle pool must be counted and stated.
- **`max_tex_tris` is 1100**, shared by ground tiles and buildings. The boat does not touch it.
- **Never add a field to `Ped` or `Car` without stating the byte cost.** `NCAR` is 18, `NPED` is 34.
- **The device build must be warning-free.** `tools/mote build games/grandthumbauto3 2>&1 | grep -c warning` must print `0`. A warning here has already cost this project one silent regression (buses stopped spawning because a line was swallowed onto an `#endif`).
- **After any device build, disassemble `mote_game_register` and confirm the literal it returns is the address of `k_vtbl`.** A NULL there is the "map failed" bug; see `docs/DEVICE_DEBUGGING.md`.
- **Do not run `tools/mote bake` on the game directory.** It rewrites *every* header in `src/`. This plan adds no art, so you should not need it at all.
- **Do not run `assets/make_citytiles.py`.** Its `ROOT` is an absolute path on another machine pointing at `games/grandthumbauto` — the wrong game.

### How this codebase verifies behaviour

There is no test framework for gameplay. The established method, used by every
feature in this game, is a **scripted headless run of the host emulator with
`fprintf(stderr, ...)` instrumentation, asserted on by eye against a stated
expected output, with the instrumentation removed before commit.** Tasks below
give you the exact command and the exact expected output. Geometry, which *can*
be tested without a frame, goes in `gta3_test_veh` and stays there.

Scripted input is `MOTE_KEYS="<key>:<startframe>-<endframe>,..."`. Key names are
`a b lb rb menu up down left right`. `MOTE_SHOT=<path> MOTE_SHOT_FRAME=<n>`
writes a PPM and exits. `MOTE_DT_MS=33` makes the clock advance one fixed step
per frame so runs are reproducible.

## Task 1: Free the RAM by folding TAXI into WAGON

The boat needs a `Gta3VehMesh`, which is 576 bytes, and only 1,020 are free.
Fold the closest remaining pair first so the budget does not go under 500.

Measured across all sixteen `SILDEF` rows on a weighted parameter distance —
`|dbody_h| + |dcab_top| + 0.6*(|dcab_z0| + |dcab_z1|) + 1.5*|dcab_w|`, against
the roughly 12 that the per-type cabin jitter (±3 roof, ±3 fore/aft) already
covers — the closest pairs are:

```
13.0  SEDAN (9 types)   COMPACT (6 types)     <- NOT this one, see below
14.4  WAGON (3 types)   TAXI    (2 types)     <- this one
15.8  COMPACT (6)       TAXI    (2)
16.8  COUPE (8)         LONGHOOD (4)
```

SEDAN/COMPACT is closer and must **not** be folded: they are the two biggest
users, 15 of the 54 car types between them, and merging them takes the
worst-case silhouette share from 17% to 28% — undoing the split that an earlier
commit made specifically to bring it down from 46%. Closest is not the same as
foldable; what matters is how much of the traffic ends up wearing one shape.

TAXI is safe to fold because a taxi's identity is no longer its shape: it is
painted yellow and carries a black roof sign, both of which are keyed on the
car *type* (`CAR_TAXI`) in `draw_vehicle_mesh` and survive the fold untouched.
What changes is that a taxi gets a wagon's slightly longer rear cabin.

## Task 5: `sail_boat` — movement that only works on water

**Files:**
- Modify: `games/grandthumbauto3/src/game.c` — a new function beside `fly_heli` (~line 2850), and the in-car control branch (~line 6709)

**Interfaces:**
- Consumes: `boat_afloat` (Task 4), `VEH_BOAT` and `VSTAT[VEH_BOAT]` (Task 3).
- Produces: `static void sail_boat(Car *c, int slot, float dt, int throttle, int brake, int steerL, int steerR)` — the same argument shape `drive_car` takes, so the call site reads the same.

Design, and why:

- **On water** the boat accelerates along its heading and turns, with the hull's
  very low `lat_damp` doing the sliding. Steering authority scales with speed:
  a rudder does nothing when the hull is not moving, which is a real property
  and also stops the boat spinning on the spot.
- **Off water** the engine produces nothing and the hull is brought to a stop.
  This is what "only runs on water" means mechanically. It cannot be a
  collision rule, because the boat is spawned at a shoreline and the tile under
  its centre will legitimately be land for a moment as it noses in.
- **Reverse** is a straight throttle reversal with no dwell. The car's
  brake-then-reverse rule exists because a car has brakes; a boat does not.

- [ ] **Step 1: Write the function**

In `games/grandthumbauto3/src/game.c`, immediately before `static void drive_car(`,
add:

```c
/* Sailing, which replaces drive_car entirely when you are in the boat.
 *
 * OFF WATER the engine does nothing and the hull stops. That is what "only runs
 * on water" means mechanically, and it has to be a movement rule rather than a
 * collision rule: the boat is moored at a shoreline, so the tile under its
 * centre is legitimately land for a moment as it noses in, and a collision rule
 * would either trap it there or shove it out.
 *
 * ON WATER the throttle drives along the heading and the rudder turns, with the
 * hull's lat_damp of 4 (against a car's 22) doing the sliding — a boat carries
 * its momentum through a turn and that falls out of the existing solver for
 * free. Steering authority scales with speed because a rudder does nothing when
 * the hull is not moving, which is both true and what stops the boat spinning
 * on the spot at a jetty.
 *
 * B is astern, not a brake: a boat has no brakes, so there is no stop-then-
 * reverse dwell of the kind drive_car needs. */
#define BOAT_ACC    6.5f     /* m/s^2 ahead */
#define BOAT_ASTERN 0.45f    /* astern is this fraction of ahead */
#define BOAT_TURN   1.15f    /* rad/s at full rudder authority */
#define BOAT_DRAG   0.55f    /* per second: a hull coasts a long way */
static void sail_boat(Car *c, int slot, float dt,
                      int throttle, int brake, int steerL, int steerR) {
    MoteBody2D *b = &bodies[slot];
    float cc = cosf(b->angle), ss = sinf(b->angle);
    float fs = b->vx*cc + b->vy*ss;                    /* speed along the hull */

    if (!boat_afloat(c->x, c->z)) {
        /* Aground. Kill the way on and give back no steering: whatever put it
         * here, it is not going anywhere under power. */
        b->vx *= 0.80f; b->vy *= 0.80f; b->avel = 0.0f;
        c->spd = 0.0f; c->lamp = LAMP_OFF;
        return;
    }

    float th = (throttle ? 1.0f : 0.0f) - (brake ? BOAT_ASTERN : 0.0f);
    fs += th * BOAT_ACC * dt;
    float cap = VSTAT[VEH_BOAT].maxspd * 1.3f;
    if (fs >  cap)        fs =  cap;
    if (fs < -cap*0.45f)  fs = -cap*0.45f;
    /* Rewrite the along-hull component and leave the lateral alone: the solver
     * owns that, which is where the slide comes from. */
    float lat = -b->vx*ss + b->vy*cc;
    b->vx = cc*fs - ss*lat;
    b->vy = ss*fs + cc*lat;

    float damp = 1.0f - mote_clampf(BOAT_DRAG * dt, 0.0f, 1.0f);
    b->vx *= damp; b->vy *= damp;

    /* Rudder authority: nothing at rest, full by a third of top speed. */
    float auth = mote_clampf(fabsf(fs) / (cap * 0.33f), 0.0f, 1.0f);
    float rud  = ((steerL ? 1.0f : 0.0f) - (steerR ? 1.0f : 0.0f)) * BOAT_TURN * auth;
    if (fs < 0.0f) rud = -rud;                         /* astern, the stern leads */
    b->avel += (rud - b->avel) * mote_clampf(4.0f*dt, 0.0f, 1.0f);
    c->yaw = b->angle;
    c->spd = fs;
    c->lamp = (th < 0.0f) ? LAMP_REV : LAMP_OFF;
}

```

Known gaps, stated rather than hidden:

- **A taxi becomes a wagon.** Task 1 trades that for the 576 bytes the boat's
  silhouette costs. It is the smallest visual loss available that does not
  concentrate a quarter of the traffic onto one shape. If this is unwanted,
  the alternative is to draw the boat from raw triangles in `draw_vehicle` the
  way the helicopter's boom and rotors are drawn — zero RAM, about 24
  triangles, and no `Gta3VehMesh` — but it gives up the mesh pipeline's
  bound-sphere culling and duplicates the colour and shadow handling.
- **Some cities have no boat.** That is deliberate (it is what makes it rarer
  than the helicopter) but it means a player can look for one that is not
  there. The `BRING` row exists partly to make that testable.
- **No NPC boats.** Water traffic is a separate feature and is not in scope.
- **The dock price lookup is already broken for the helicopter**, and Task 3
  Step 5b fixes it rather than working around it. `SELL[CAR_CLS[c->type]]`
  indexes a 54-entry table with `VEH_HELI` = 56, three past the end, and then
  indexes a 19-entry table with the byte that comes back. That is a live
  out-of-bounds read in shipped code; the boat only makes it easy to reach,
  since a boat at a pier is exactly where you would be. The fix gives every
  non-car type its own price and guards the array with `c->type < CARS2_N`.
